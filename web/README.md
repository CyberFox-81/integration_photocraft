## Embedding bridge

Started with `?host=parent` inside an iframe, PhotoCraft talks to its parent window with `postMessage`. It only accepts messages from the parent window on its own origin, and only sends to that origin. Every message is a plain object with a `type`:

| Message | Direction | Fields | Meaning |
|---|---|---|---|
| `photocraft:ready` | PhotoCraft → parent | `version` | The app is listening; send a file now. |
| `photocraft:open` | parent → PhotoCraft | `name`, `bytes` (`ArrayBuffer` or `Uint8Array`) | Open this file, as File › Open would. |
| `photocraft:pick-save` | PhotoCraft → parent | `id`, `name` | Save As or Export asks where to save; `name` is the suggested file name (its extension sets the format). |
| `photocraft:picked` | parent → PhotoCraft | `id`, `path` | The answer; a missing or empty `path` cancels. |
| `photocraft:save` | PhotoCraft → parent | `name`, `bytes` (transferred `ArrayBuffer`) | A file PhotoCraft would otherwise download: Save, Save As or Export. `name` is a file name, or a path the parent picked. The parent stores the file and reports success or failure itself. |
| `photocraft:dirty` | PhotoCraft → parent | `dirty` (boolean) | Unsaved changes appeared or went away. |
| `photocraft:failed` | PhotoCraft → parent | `error` | The app couldn't start (for example, no WebGPU or WebGL2). |

With `?host=parent`, Save, Save As and Export ask the parent where to save (`photocraft:pick-save`), what PhotoCraft writes goes to the parent instead of the browser's downloads, and the parent (not PhotoCraft) guards leaving the page with unsaved changes. File › Open keeps the browser's own file picker.

Without `?host=parent`, PhotoCraft behaves exactly as upstream: saved files download.
